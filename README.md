# УВМ: ассемблер и интерпретатор (вариант 26)

Python 3.10+, сторонние библиотеки не нужны.

## Язык ассемблера

Одна команда на строку: `мнемоника операнд, операнд`.
Комментарий начинается с `;`. Регистр: `r<N>`. Число: десятичное или `0x..`.
Мнемоники не зависят от регистра букв.

| Команда | Запись | A | Поля | Действие |
|---|---|---|---|---|
| Загрузка константы | `ldc r<C>, <B>` | 22 | B: 30 бит (5-34), C: 6 бит (35-40) | `reg[C] = B` |
| Чтение из памяти | `ld r<B>, <C>` | 0 | B: 6 бит (5-10), C: 17 бит (11-27) | `reg[B] = mem[C]` |
| Запись в память | `st r<B>, r<C>` | 16 | B: 6 бит (5-10), C: 6 бит (11-16) | `mem[reg[B]] = reg[C]` |
| Циклический сдвиг вправо | `ror r<B>, <C>` | 4 | B: 6 бит (5-10), C: 17 бит (11-27) | `reg[B] = ror(reg[B], mem[C])` |

Размер команды 6 байт, A занимает биты 0-4.

## Запуск

В Linux вместо `python` используйте `python3` (или установите пакет `python-is-python3`).
Ассемблер (на этапе 1 режим `--test` печатает поля команд):

    python -m uvm.assembler examples/spec_tests.asm out.bin --test

Ожидаемый вывод:

    A=22, B=638, C=25
    A=0, B=10, C=28
    A=16, B=54, C=15
    A=4, B=55, C=454

## Интерпретатор

    python -m uvm.interpreter <бинарный файл> <дамп.json> --from <адрес> --to <адрес>

Выполняет программу и сохраняет дамп памяти данных в JSON. Диапазон адресов
включает оба конца. Формат дампа: объект `{"адрес": значение}`.

### Модель памяти

- Память команд хранит 6-байтовые команды из бинарного файла и отделена от памяти данных.
- Память данных: 131072 слова (адрес кодируется 17 битами поля C).
- Регистры: 64 штуки (номер кодируется 6 битами поля B или C).
- Слово: 32 бита, при записи значение обрезается до 32 бит.
- Обращение к адресу вне памяти завершает программу с ошибкой.

### Пример: копирование массива

    python -m uvm.assembler examples/copy_array.asm copy_array.bin
    python -m uvm.interpreter copy_array.bin dump.json --from 200 --to 204

Содержимое `dump.json`:

    {
      "200": 11,
      "201": 22,
      "202": 33,
      "203": 44,
      "204": 55
    }

### Команда ror

`ror r<B>, <C>`: регистр `B` циклически сдвигается вправо на число бит,
хранящееся в памяти данных по адресу `C`. Результат записывается в регистр `B`.
Сдвиг берётся по модулю 32, поэтому сдвиг на 0 и на 32 не меняет значение.
Если величина сдвига не записана, в ячейке лежит 0 и значение не меняется.

### Пример: сдвиг с сохранением результата

    python3 -m uvm.assembler examples/ror_demo.asm ror_demo.bin
    python3 -m uvm.interpreter ror_demo.bin dump.json --from 20 --to 21

Содержимое `dump.json`:

    {
      "20": 2166572391,
      "21": 2147483648
    }

Здесь `2166572391` это `0x81234567` (`0x12345678` сдвинуто на 4),
а `2147483648` это `0x80000000` (`1` сдвинуто на 1).

## Тестовая задача: поэлементный ror над векторами

Над двумя векторами длины 7 выполняется `result[i] = ror(A[i], B[i])`.
Результат записывается в новый вектор.

| Вектор | Адреса памяти данных |
|---|---|
| A | 0..6 |
| B | 10..16 |
| Результат | 20..26 |

Программы формирует `uvm/vector_program.py`: `python3 -m uvm.vector_program`
пересоздаёт `examples/vector_ror_1.asm`, `vector_ror_2.asm`, `vector_ror_3.asm`.

Запуск (пример 1):

    python3 -m uvm.assembler examples/vector_ror_1.asm vector_ror_1.bin
    python3 -m uvm.interpreter vector_ror_1.bin dump.json --from 20 --to 26

### Примеры

| Пример | A | B | Результат (hex) |
|---|---|---|---|
| 1 | 1, 2, 4, 8, 16, 32, 64 | 1, 1, 1, 1, 1, 1, 1 | 80000000, 1, 2, 4, 8, 10, 20 |
| 2 | 1, 1, 1, 1, 1, 1, 1 | 0, 1, 4, 8, 16, 31, 32 | 1, 80000000, 10000000, 1000000, 10000, 2, 1 |
| 3 | 12345678 (все 7) | 4, 8, 12, 16, 20, 24, 28 | 81234567, 78123456, 67812345, 56781234, 45678123, 34567812, 23456781 |

Дамп примера 1 (`dump.json`):

    {
      "20": 2147483648,
      "21": 1,
      "22": 2,
      "23": 4,
      "24": 8,
      "25": 16,
      "26": 32
    }
